Eliza

 

 

ELIZA é um programa de conversação em linguagem natural descrito por Joseph Weizenbaum em janeiro de 1966 [1].
Apresenta o diálogo entre um usuário humano (Você) e um programa de computador representando um psicoterapeuta rogeriano.
O programa original foi implementado no IBM 7094 do sistema de compartilhamento de tempo do Project MAC no MIT e foi escrito em MAD-SLIP.

Foi assim que Joseph Weizenbaum discutiu sua escolha por um modelo de conversa, como seria encontrado na sessão do psicoterapeuta:
ELIZA tem um melhor desempenho quando seu correspondente humano é inicialmente instruído a "falar" para ele, através da máquina de escrever, é claro, assim como alguém faria para um psiquiatra. Este modo de conversa foi escolhido porque a entrevista psiquiátrica é um dos poucos exemplos de linguagem natural diádica categorizada de comunicação em que um dos participantes é livre para assumir a postura de saber quase nada do mundo real. Se, por exemplo, alguém fosse dizer a um psiquiatra "Fiz um longo passeio de barco" e ele respondesse "Diga-me sobre barcos", não se poderia supor que ele não sabia nada sobre barcos, mas que ele tinha algum propósito em direcionar a conversa subsequente. É importante observar que essa suposição é feita pelo falante. Seja realista ou não, é uma questão totalmente distinta. Em qualquer caso, tem uma utilidade psicológica crucial na medida em que serve ao falante para manter sua sensação de ser ouvido e compreendido. O falante ainda defende sua impressão (que mesmo na vida real pode ser ilusória), atribuindo ao seu parceiro de conversa todo tipo de conhecimento prévio, percepções e capacidade de raciocínio. Mas novamente, essas são as contribuições do falante para a conversa.
Para uma conversa de exemplo, veja a página: Teste da Eliza.
 

Sobre o elizabot.js

"elizabot.js" é uma biblioteca JavaScript orientada a objetos para [múltiplas] instâncias do programa Eliza.

Sinopse:

         new ElizaBot( <flag-desativar-escolha-aleatoria> )
         ElizaBot.prototype.transform( <string-de-entrada> )
         ElizaBot.prototype.getInitial()
         ElizaBot.prototype.getFinal()
         ElizaBot.prototype.reset()

Uso:

         var eliza = new ElizaBot();
         var initial = eliza.getInitial();
         var reply = eliza.transform(inputstring);
         if (eliza.quit) {
             // a última entrada do usuário foi uma frase de saída
         }

         // o método `transform()' retorna uma frase final caso seja uma frase de saída,
         // mas você também pode obter uma frase final com:
         var final = eliza.getFinal();

         // outros métodos: reiniciar memória e estado interno
         eliza.reset();

         // para definir o tamanho da memória interna, sobrescreva a propriedade `memSize':
         eliza.memSize = 100; // (padrão: 20)

         // para reproduzir a conversa de exemplo dada por J. Weizenbaum
         // inicialize com a flag opcional de desativar escolha aleatória
         var originalEliza = new ElizaBot(true);

Como o ElizaBot é um objeto totalmente independente e as instâncias usam sua própria memória interna, é possível ter múltiplas instâncias do objeto ElizaBot conversando entre si.

O ElizaBot também é um motor genérico de chatbot que pode ser alimentado com qualquer conjunto de regras.

Estruturas de Dados (cf: "elizadata.js"):

         elizaInitials ......... Array de frases iniciais
         elizaFinals  .......... Array de frases finais
         elizaQuits ............ Array de frases de saída
         elizaPres ............. Array de pares de substituição alternados para pré-processamento
         elizaPosts ............ Array de pares de substituição alternados para pós-processamento
         elizaSynons ........... Objeto de palavras e seus sinônimos (como array)
         elizaPostTransforms ... Pares de regexp/substituição executados como limpezas finais
         elizaKeywords ......... Array de palavras-chave com decomposições e reconstruções

         elementos de elizaKeywords são do tipo:
       
         ["<chave>", <peso>,
           [
             [ // primeiro padrão de decomposição
               "<decomp>",
               ["<reasmb>", "<reasmb>", "<reasmb>"]
             ],
             [ // segundo padrão de decomposição
               "<decomp>",
               ["<reasmb>", "<reasmb>", "<reasmb>"]
             ]
           ]
         ]

         palavras-chave com peso maior têm prioridade.
         decomposições são comparadas na ordem de definição.
         reconstruções são escolhidas aleatoriamente ou alternadas se a flag sem-aleatoriedade estiver ativa.
 
         a palavra-chave especial "xnone" guarda as regras para frases padrão (sem correspondência).
         
         sintaxes de decomposição e reconstrução seguem a forma "canônica":

         decomposição:
           * ... quaisquer palavras (incluindo nenhuma)
           $ ... (na primeira posição) reconstrói apenas para memória
           @synon ... substitui entrada pela expressão de sinônimos

         reconstrução:
           (n) ... insere o parâmetro da posição n (a primeira é "1")
                   posições são quaisquer correspondências de "*" ou "@synon"

         pres, posts, sinônimos, palavras-chave e decomposições, todos em minúsculas.
         todas as definições são opcionais, mas pelo menos elizaKeywords deve ser fornecida.
         se nenhuma palavra-chave for encontrada, `transform()' retorna a string padrão:
         "Não tenho palavras para responder.".

Nota:   "elizaPostTransforms" não é um recurso padrão da ELIZA e foi incluído para fornecer
         um mecanismo de suavização para quaisquer produções em uma conversa robô-para-robô.

As representações de dados e a sintaxe seguem a forma "canônica".
(Como todos os dados são transformados e comparados como expressões regulares, você também pode usar regexps nas palavras-chave e decomposições. Não use expressões com "*" em padrões de decomposição, pois o próprio "*" será transformado em um padrão regexp.)
A estrutura do "elizaKeywords" segue o modelo de dados interno conforme descrito por J. Weizenbaum em seu artigo [1].
